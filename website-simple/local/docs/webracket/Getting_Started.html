2 Getting Started🔗

2.1 What is WebRacket?🔗

WebRacket is a compiler and runtime that lets you write programs in Racket and run them in the browser by compiling them to WebAssembly.

In practice, it gives you:

  • a subset of Racket

  • compiled to fast, portable WebAssembly

  • with direct access to browser APIs and JavaScript

2.1.1 How it works🔗

  • You write a Racket program (.rkt)

  • WebRacket compiles it to a number of WebAssembly (.wasm) files.

    • one corresponds to your program

    • one to the runtime (shared between programs)

    • one for FFI libraries

  • a webpage that loads the webassembly files

  • The browser runs the result

2.2 What you can build🔗

WebRacket is aimed at building interactive programs that run in the browser.

2.2.1 Web applications🔗

You can build dynamic web pages and small applications with user interaction, event handling, and DOM manipulation.

2.2.2 Graphics and visualizations🔗

Using the canvas API, you can create drawings, animations, and interactive visualizations.

2.2.3 Multimedia applications🔗

WebRacket supports audio APIs, making it possible to build sound-based tools, synthesizers, and interactive audio applications.

2.2.4 Browser-integrated tools🔗

You can access standard browser features such as:

  • the DOM

  • event handling

  • local storage and IndexedDB

  • network communication via fetch and WebSocket

2.3 Your First Program🔗

This section shows a minimal WebRacket program that renders a simple "Hello World" page in the browser.

2.3.1 Step 1: Write a program🔗

Create a file named hello.rkt with the following contents:

"hello.rkt"

#lang webracket/base

 

(require web-easy)

 

(define hello-world-app

  (window

    (container

      (h1 "Hello World")

      (text "Have a nice day."))))

 

(mount-renderer!

 (render hello-world-app))

2.3.2 Step 2: Compile the program🔗

Compile the program for the browser:

webracket --browser --dest generated hello.rkt
webracket --browser --dest generated hello.rkt

The same compiler is also available as raco webracket. When working from an uninstalled source checkout, use racket webracket.rkt in place of webracket.

This generates the files needed to run the program in a browser. The exact set of generated files depends on the libraries the program uses. For this example, expect a host page hello.html, the user program hello.wasm, a reusable runtime module named like webracket-runtime-<fingerprint>.wasm, a label-map file hello.wasm.map.sexp, and possibly a reusable FFI module named like webracket-ffi-<fingerprint>.wasm. Keep the generated files together.

2.3.3 Step 3: Start a local web server🔗

To run the program in a browser, start a local web server in the directory containing the generated files:

If the default port 8000 is already in use, add an -p 8001 to the command.

cd generated
raco static-web
cd generated raco static-web

By default, this starts a local server and prints the address to use in your browser.

2.3.4 Step 4: Open the page in your browser🔗

Open the address shown by raco static-web, then load hello.html. With the default port, the page is:

http://localhost:8000/hello.html

Serve the files over HTTP; do not open hello.html directly as a file:// page.

You should see a page containing the heading Hello World and the text Have a nice day.

If you want to inspect or call selected WebRacket bindings from the browser’s JavaScript console while a page is running, see The Browser Console Bridge.

2.3.5 What this program does🔗

The calls to window, container, h1, and text construct a description of the user interface. The call to render produces a renderer for the interface. The call to mount-renderer! inserts it into the browser page.

2.4 Mental Model🔗

This section gives a high-level picture of how a WebRacket program runs.

2.4.1 From Racket to the browser🔗

A WebRacket program goes through the following steps:

  • You write a program in Racket.

  • The WebRacket compiler translates it to WebAssembly modules.

  • A generated host page loads the runtime, any FFI module, and the user program.

  • The browser executes the cooperating modules.

In short:

Racket → WebRacket compiler → Wasm modules + host page → Browser

2.4.2 What runs where🔗

A WebRacket program involves three parts:

  • WebAssembly: Your compiled program runs with reusable runtime and FFI modules.

  • JavaScript: The generated host page loads the Wasm modules and connects them to the browser.

  • The browser: Provides the DOM and other APIs.

Your Racket code does not run directly in JavaScript. Instead, it runs inside WebAssembly and interacts with the browser through the provided libraries and FFI.

2.4.3 Producing output🔗

Unlike a traditional Racket program, output is not shown in a terminal.

To display something in the browser, your program must construct a user interface and insert it into the page. For example:

  • Using web-easy to build and display UI elements.

  • Using DOM libraries to create and modify elements.

Calling render creates a representation of the interface, and mount-renderer! inserts it into the page so it becomes visible.

2.4.4 A different kind of program🔗

WebRacket programs are typically:

  • interactive

  • event-driven

  • running continuously in the browser

Instead of computing a result and exiting, a program usually reacts to user input such as clicks, key presses, or network events.

2.4.5 Summary🔗

A WebRacket program:

  • is written in Racket

  • compiled to WebAssembly

  • runs inside the browser

  • interacts with the page through libraries and FFI
