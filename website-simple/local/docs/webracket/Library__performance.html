45 Library: performance🔗

 (include-lib performance)

 Compile option:  --ffi dom

The performance library is a browser stopwatch and logbook for the current page.

Use it when you want to measure how long something takes, record named marks, or inspect timing data from the current page. The API stays close to the MDN names, but the wrapper adds a little validation and keeps the common calls easy to read from WebRacket.

The Performance API is mostly about:

  • reading timestamps and page timing metadata

  • creating marks and measures for your own code

  • querying the browser’s recorded performance entries

The performance-event-counts helper returns either #f or a performance-event-counts-info value that wraps the browser’s EventCounts object.

The performance-memory helper returns either #f or a performance-memory-info value that wraps the browser’s memory information object.

45.1 Performance Quick Start🔗

Start by including the library, taking a timestamp, and measuring a small piece of work.

; Include the checked performance wrapper library.
(include-lib performance)
 
; Capture the starting timestamp.
(define start (performance-now))
 
; Do the work you want to measure.
(define total (for/sum ([n (in-range 1000)]) n))
 
; Capture the ending timestamp and compute the duration.
(define elapsed (- (performance-now) start))

The quick start shows the simplest path: call performance-now before and after the work you care about, and subtract the results. After this block, start holds the starting timestamp, elapsed holds the duration, and total holds the computed sum.

45.2 Performance Example🔗

This example uses named marks and a measure entry. Named marks are useful when you want to keep a browser-friendly breadcrumb trail for a piece of work, not just a raw duration.

; Include the performance wrapper library.
(include-lib performance)
 
; Clear any old marks or measures with the same names.
(performance-clear-marks "compile-start")
(performance-clear-measures "compile-span")
 
; Record the start of the work.
(performance-mark "compile-start")
 
; Pretend to do some work.
(define total (for/sum ([n (in-range 1000)]) n))
 
; Record the end of the work and create a measure entry.
(performance-mark "compile-end")
(performance-measure "compile-span" "compile-start" "compile-end")
 
; Look up the entries that were just created.
(define marks (performance-get-entries-by-name "compile-start"))
(define measures (performance-get-entries-by-name "compile-span" "measure"))

The example shows the usual workflow: clear any old entries, create a start mark, do the work, create an end mark, and then ask the browser for the recorded measure. After this block, marks and measures hold the browser entry lists for the mark and measure names, and total holds the computed sum.

45.4 Performance EventCounts Map🔗

The browser’s EventCounts map is a little table that records how many times certain event types, such as "click", have been dispatched on the current page. It is useful when you want to inspect interaction activity without dealing with the browser’s raw JavaScript object directly.

The map-like helpers let you inspect the counts for a particular event type without dropping back to the raw browser object.

The performance-event-counts-info struct keeps that browser object tucked away in a single field. That gives the wrapper room to grow with additional helpers without exposing the raw external value as the main user-facing result.

The iterator-returning helpers on the map, such as performance-event-count-map-entries, return wrapped iterator values rather than raw browser iterator objects, so you can pass them directly to helpers such as iterator->vector or inspect the next step directly with the iterator helpers.

struct

(struct performance-event-counts-info (raw)
    #:extra-constructor-name make-performance-event-counts-info)
  raw : external/raw
Wraps a browser EventCounts object in the checked struct used by performance-event-counts.

procedure

(performance-event-count-map-size counts)

 → exact-nonnegative-integer?

procedure

procedure

(performance-event-count-map-get counts 
  event-type) 
 → (or/c #f exact-nonnegative-integer?)
  counts : performance-event-counts-info?
  event-type : (or/c string? symbol?)

 MDN  EventCounts: get() method

Returns the count for the named event type, or #f when the browser does not expose a value for that type. The event type accepts a string or symbol and is normalized to a string.

procedure

(performance-event-count-map-has? counts    
  event-type) → boolean?
  counts : performance-event-counts-info?
  event-type : (or/c string? symbol?)

 MDN  EventCounts: has() method

Returns #t when the browser exposes a count for the named event type. The event type accepts a string or symbol and is normalized to a string.

procedure

(performance-event-count-map-for-each counts    
  proc) → void?
  counts : performance-event-counts-info?
  proc : (or/c procedure? external?)

 MDN  EventCounts: forEach() method

The raw proc argument, when supplied as an external, should be a browser JavaScript function value. Calls proc for each event-count entry in the browser map. The callback receives the count first, the event type second, and the EventCounts map itself third, just like the underlying JavaScript map-style API.

45.5 Performance Memory Info🔗

The browser’s memory information object reports the JavaScript heap limits and usage for the current page. It is useful when you want to see how much browser-managed memory your page is using, but it is a browser-specific feature and may be unavailable.

struct

(struct performance-memory-info (raw)
    #:extra-constructor-name make-performance-memory-info)
  raw : external/raw
Wraps the browser memory information object used by performance-memory.

procedure

(performance-memory-info-js-heap-size-limit memory-info)

 → exact-nonnegative-integer?
  memory-info : performance-memory-info?
Returns the JavaScript heap size limit reported by the browser.

procedure

(performance-memory-info-total-js-heap-size memory-info)

 → exact-nonnegative-integer?
  memory-info : performance-memory-info?
Returns the browser’s total JavaScript heap size.

procedure

(performance-memory-info-used-js-heap-size memory-info)

 → exact-nonnegative-integer?
  memory-info : performance-memory-info?
Returns the browser’s currently used JavaScript heap size.
