48 Library: storage🔗

 (include-lib storage)

 Compile option:  --ffi dom

The Web Storage API gives browsers a simple synchronous key/value store. It is the usual choice when a page needs a small amount of client-side state that should be available through localStorage or sessionStorage.

In WebRacket, the storage library provides checked wrappers for the browser Storage object. That lets programs read and write browser storage without handling raw JavaScript objects directly.

 MDN  Storage API

The two storage areas behave slightly differently:

  • session-storage is partitioned by both browser tab and origin, so each tab gets its own origin-scoped area and the data disappears when the tab closes

  • local-storage is partitioned by origin only, so every document with the same origin shares the same area and the data survives browser restarts

Both storage areas are synchronous, so a large amount of storage work can block other browser activity while it runs. String-like arguments accept either strings or symbols.

48.1 Storage Quick Start🔗

; Include the storage wrapper library.
(include-lib storage)
 
; Read the two built-in browser storage areas.
(define ls (local-storage))
(define ss (session-storage))
 
; Store a value and read it back later.
(storage-set-item! ls 'webracket-demo "123")
(storage-get-item ls 'webracket-demo)

procedure
