10 Callback Source-Map Tool🔗

This chapter documents the helper script tools/find-callback-source.rkt.

The tool is meant for callback debugging. When WebRacket reports a callback error, the message may include a debug label such as label.4054. That label is emitted by the compiler and also recorded in the generated .wasm.map.sexp file.

The tool lets you go from:

  • a callback error message containing debug-id: label.N

  • to the corresponding source file, line, and column

10.1 When To Use It🔗

Use this tool when:

  • a browser or Node callback error names a failing callback with a debug-id

  • you want to find the source location for the generated callback label

  • you want to inspect the source form recorded in the label map

Typical workflow:

  • Reproduce the callback error.

  • Copy the debug-id label from the error message.

  • Run tools/find-callback-source.rkt on the corresponding .wasm.map.sexp file.

10.2 Basic Usage🔗

The command takes two required arguments:

  • the path to a .wasm.map.sexp file

  • the label to look up, such as label.4054

Example

racket tools/find-callback-source.rkt test/test-ffi.wasm.map.sexp label.5792
racket tools/find-callback-source.rkt test/test-ffi.wasm.map.sexp label.5792

The output prints:

  • the label

  • the source path

  • the source line and column

  • the recorded span

  • the same-as target when present

Example output shape:

  label: label.5792

  source: /path/to/file.rkt:667:32

  span: 3482

10.3 Showing The Recorded Form🔗

When the label map was generated with form payloads enabled, the tool can also print the recorded source form.

Use --show-form:

racket tools/find-callback-source.rkt --show-form web-site-new/src/test-toc.wasm.map.sexp label.4054
racket tools/find-callback-source.rkt --show-form web-site-new/src/test-toc.wasm.map.sexp label.4054

Example output shape:

  label: label.4054

  source: /path/to/file.rkt:107:2

  span: 135

  form: "(let-values ...)"

10.4 Relationship To Callback Errors🔗

Callback errors can now include a machine-oriented debug identifier:

  WebRacket callback error

    kind: arity-mismatch

    name: on-click

    id: 0

    debug-id: label.4054

    expected: 0

    argc: 1

    detail: callback arity mismatch

In that case, use the label from the debug-id line directly:

racket tools/find-callback-source.rkt path/to/program.wasm.map.sexp label.4054
racket tools/find-callback-source.rkt path/to/program.wasm.map.sexp label.4054

10.5 Requirements🔗

The tool expects the generated source map file produced by the normal WebRacket compiler flow:

  • program.wasm.map.sexp

The source-form output depends on the label map including form payloads. Maps omit those heavyweight payloads by default. If the map was generated without --label-map-forms, source locations still work, but --show-form may print nothing for the form.

10.6 Notes🔗

  • The tool is read-only. It does not modify the source map.

  • The label only needs to be stable within one build artifact set. Use the .wasm.map.sexp file that was produced together with the failing program.

  • Some entries are aliases recorded with same-as. The tool prints that alias target when present.
