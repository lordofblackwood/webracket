51 Library: websocket🔗

 (include-lib websocket)

 Compile option:  --ffi websocket

WebSockets are a browser technology for keeping a connection open between a web page and a server.

With ordinary HTTP, the browser sends a request and waits for a single response. With WebSockets, the connection stays open after the initial handshake. That means the browser and server can both send messages at any time.

This is useful whenever the page needs live, bidirectional updates:

  • chat and messaging

  • live dashboards and notifications

  • collaborative editing

  • multiplayer games and remote controls

The websocket library is the checked, high-level API for WebSocket programs in WebRacket. It is implemented on top of the lower-level ffi/websocket.ffi bindings, but application code should normally use the websocket-* functions documented on this page.

String-like WebSocket arguments accept either strings or symbols, and the wrapper converts symbols to their string names. Optional arguments use #f to mean that the argument is omitted.

The websocket-new constructor returns a wrapped websocket value. Use websocket-raw only when you need to inspect the underlying browser object directly.

51.1 WebSocket Quick Start🔗

To use WebSockets, create a connection, install the handlers you need, and send messages when you are ready.

; Include the WebSocket library.
(include-lib websocket)
 
; Open a WebSocket connection.
(define ws (websocket-new "wss://echo-websocket.fly.dev/"))
 
; Run code when the connection opens.
(websocket-onopen! ws
  (lambda (evt)
    (displayln "connected")))
 
; Run code when a message arrives.
(websocket-onmessage! ws
  (lambda (evt)
    (displayln "message received")))
 
; Send a message over the connection.
(websocket-send ws "hello")

When you are done with a connection, call websocket-close. If your page is served over https, use wss:// rather than ws://.

51.2.2 WebSocket Construction and State🔗

procedure

(websocket-new url protocol ...) → websocket?

  url : (or/c string? symbol?)
  protocol : (or/c string? symbol?)

 MDN  WebSocket() constructor

Creates a new WebSocket connection to url.

The raw url argument may be a string or a symbol. Symbols are converted to strings before the browser constructor is called.

Provide zero or more protocol names after url to select the subprotocols the client is willing to speak.

Each protocol name may be a string or a symbol. Symbols are converted to strings before the low-level WebSocket binding is called.

Common protocol names include "chat", "json", "metrics", and "sync-v2", but the server and client must agree on the actual names.

procedure

(websocket-url ws) → string?

  ws : websocket?

Returns the connection URL associated with ws.

procedure

(websocket-ready-state ws) → symbol?

  ws : websocket?

 MDN  WebSocket: readyState property

Returns the browser readyState value for ws as a symbol.

The returned symbols are 'connecting, 'open, 'closing, and 'closed.

procedure

(websocket-ready-state-number ws) → exact-nonnegative-integer?

  ws : websocket?

 MDN  WebSocket: readyState property

Returns the browser readyState number for ws.

The usual WebSocket state numbers are:

  • 0: connecting

  • 1: open

  • 2: closing

  • 3: closed

procedure

(websocket-buffered-amount ws) → exact-nonnegative-integer?

  ws : websocket?

procedure

  ws : websocket?

Returns the negotiated subprotocol string, or an empty string if no subprotocol was selected.

procedure

51.2.3 WebSocket Sending and Closing🔗

procedure

(websocket-send ws data) → void?

  ws : websocket?
  data : (or/c string? symbol? bytes? external?)

 MDN  WebSocket: send() method

Sends data through the WebSocket connection.

The raw data argument can be a browser ArrayBuffer, Uint8Array, or Blob value, or a Racket bytes value. If data is a symbol, the wrapper converts it to its string name first.

procedure

(websocket-close ws [code reason]) → void?

  ws : websocket?
  code : exact-integer? = 1000
  reason : (or/c #f string? symbol?) = #f

 MDN  WebSocket: close() method

Closes the WebSocket connection.

If code is omitted, the wrapper uses the browser default close code 1000. If reason is omitted or #f, no reason string is sent. If reason is a symbol, the wrapper converts it to its string name before closing the socket.

51.2.4 WebSocket Event Handlers🔗

WebSocket event handlers are ordinary callback procedures that the browser calls when something happens on the socket. Each handler is stored in a property such as onopen or onmessage. Setting the handler to #f clears it, which means the browser stops calling that callback for future events.

The shared event library provides the browser event accessors used by message and close handlers, such as message-event-data and close-event-code.

51.2.5 WebSocket Event Example🔗

This example shows the usual pattern: include both libraries, install handlers, and inspect the browser event values with the shared event helpers.

; Include the checked WebSocket and event libraries.
(include-lib websocket)
(include-lib event)
 
; Open a WebSocket connection.
(define ws (websocket-new "wss://echo-websocket.fly.dev/"))
 
; Log the message payload when a message arrives.
(websocket-onmessage! ws
  (lambda (evt)
    (displayln (message-event-data evt))))
 
; Log the close code when the connection closes.
(websocket-onclose! ws
  (lambda (evt)
    (displayln (close-event-code evt))))

The event accessors shown here are shared with the standalone event library, so other browser code can use the same MessageEvent and CloseEvent helpers.

51.2.6 WebSocket Event Listeners🔗

procedure

(websocket-add-event-listener! ws    
  event-name    
  listener    
  options ...) → external?
  ws : websocket?
  event-name : (or/c string? symbol?)
  listener : (or/c procedure? external?)
  options : (or/c boolean? external?)

 MDN  EventTarget: addEventListener() method

The raw listener argument, when supplied as an external, should be a browser callback function. The optional options values can be booleans or a browser AddEventListenerOptions object.

Registers listener for the named browser event and returns the installed callback token.

Any additional positional values after listener are forwarded to the browser addEventListener call unchanged.

The most common option form is a capture flag such as #t or #f. You can also pass a JavaScript options object that uses fields such as capture, once, passive, and signal.

procedure

(websocket-remove-event-listener! ws    
  event-name    
  listener    
  options ...) → void?
  ws : websocket?
  event-name : (or/c string? symbol?)
  listener : (or/c procedure? external?)
  options : (or/c boolean? external?)

 MDN  EventTarget: removeEventListener() method

The raw listener argument, when supplied as an external, should be a browser callback function. The optional options values can be booleans or a browser AddEventListenerOptions object.

Removes a previously registered listener for the named browser event.

The listener can be either the original procedure or the token returned by websocket-add-event-listener!. Any additional positional values after listener are forwarded to the browser removeEventListener call unchanged.

Use the same option values here that you used when adding the listener, for example a capture flag or the same JavaScript options object.
